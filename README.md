# Дело — список задач

Небольшое веб-приложение для управления повседневными задачами. Тестовое задание на позицию начинающего разработчика с AI.

[Открыть работающий сайт](https://rutik554.github.io/delo-todo/)

## Возможности

- Добавление задачи кнопкой или Enter.
- Отметка выполнения и возвращение задачи в работу.
- Удаление задач.
- Сохранение в localStorage после каждого изменения, восстановление при открытии страницы.
- Фильтры «Все», «В работе», «Готово» и индикатор прогресса.
- Адаптивная вёрстка, управление с клавиатуры и подписи для скринридеров.
- Проверка пустого ввода и обработка ошибок хранилища.

## Технологии и запуск

HTML, CSS и JavaScript без фреймворков и зависимостей. Для четырёх основных операций отдельный фреймворк и сервер не требуются.

Откройте терминал в папке проекта:

```sh
python -m http.server 8080 --directory dist
```

Перейдите на http://localhost:8080. Альтернатива — расширение Live Server в VS Code с папкой `dist`.

## Структура

```text
dist/
  index.html   — семантическая разметка
  styles.css   — стили и адаптивная вёрстка
  app.js       — операции с задачами, фильтры и localStorage
README.md
```

`tasks` хранит массив объектов `{ id, text, completed }`. Изменения сначала записываются в localStorage, затем интерфейс перерисовывается функцией `render()`. Текст пользователя добавляется через `textContent`, поэтому не интерпретируется как HTML. Событие `storage` обновляет список при изменениях в другой вкладке.

Данные хранятся только в текущем браузере и для текущего адреса сайта. Очистка данных браузера удаляет задачи. Без доступа к localStorage приложение сообщает о невозможности сохранения. Google Fonts используется только для шрифта; при недоступности сети работает системный шрифт.

## Публикация на GitHub Pages

1. Создайте репозиторий в GitHub и загрузите код.
2. В Settings → Pages выберите GitHub Actions.
3. В репозитории уже есть workflow `.github/workflows/pages.yml`: после push в `main` он опубликует папку `dist`.
4. Ссылка на сайт появится в разделе Pages после успешного завершения workflow.

## Проверка вручную

1. Добавить задачу кнопкой и вторую через Enter.
2. Проверить, что пробелы не создают задачу.
3. Отметить задачу выполненной; проверить фильтры и прогресс.
4. Перезагрузить страницу: текст и отметки должны сохраниться.
5. Удалить задачу; перезагрузить страницу и убедиться, что она не вернулась.
6. Проверить длинный текст, узкий экран и управление Tab/Space/Enter.
7. Ввести `<img src=x onerror=alert(1)>`: строка должна отобразиться как обычный текст.
